❄️ Git & GitHub 팀 협업 가이드북

🙋‍♂️ [팀원] 작업 및 PR 요청 매뉴얼

1. 기존 파일 삭제 후 새롭게 프로젝트 내려받기 (초기 1회)

  1. VS Code 상단 메뉴 File ➔ Close Folder 클릭 (열린 폴더 닫기)
  2. 기존 프로젝트 폴더를 내 컴퓨터에서 완전 삭제
  3. 새 작업용 폴더 생성 (예: 바탕화면에 winter 폴더 생성)
  4. VS Code에서 File ➔ Open Folder...로 새로 만든 폴더 열기
  5. 상단 메뉴 Terminal ➔ New Terminal을 열고 아래 명령어 입력:
git clone https://github.com/2026-08-26/team_winter.git .
💡 명령어 맨 뒤에 한 칸 띄우고 점(.)을 붙이면 새 폴더 안에 깔끔하게 파일만 다운로드됩니다.

2. 개인 작업 브랜치 만들기 & 파일 수정 후 Upload

  1. 내 전용 브랜치 만들기: git checkout -b feature/yg
  2. VS Code에서 코드 수정 후 Ctrl + S로 파일 저장
  3. 장바구니 담기: git add . (또는 특정 파일 지정: git add 미니프로젝트/영근.html)
  4. 저장 기록 남기기: git commit -m "영근페이지 디자인 수정"
  5. GitHub 올리기: git push origin feature/yg

3. GitHub 웹사이트에서 검수 요청 (PR 생성)

  1. GitHub 팀 저장소 페이지 접속
  2. 메인 상단에 뜨는 노란색 Compare & pull request 버튼 클릭
  3. 메시지 작성: "팀장님, 영근.html 수정했으니 검토 후 master에 합쳐주세요!"
  4. 초록색 Create pull request 버튼 클릭하면 완료!
🚨 Push 후 PR 버튼이 바로 안 뜰 때 (수동 PR 방법):
1. 상단 Pull requests 탭 ➔ 우측 New pull request 클릭
2. 브랜치 선택: base: master ⬅ compare: feature/yg 선택
3. 초록색 Create pull request 클릭 후 제출

4. 다른 팀원의 PR이 Merge 되었을 때 (작업 중 동기화)

다른 팀원이 먼저 PR을 올리고 master에 반영되었다면, 충돌 방지를 위해 내 브랜치도 최신화해 두는 것이 안전합니다.

  1. 작업 중인 내용 먼저 저장 (필수):
    git add . git commit -m "작업 중간 저장"
  2. 최신 master 가져와서 내 브랜치에 합치기:
    git checkout master git pull origin master git checkout feature/yg git merge master
  3. 이어서 남은 작업을 진행하고 추후 동일하게 push 및 PR을 생성합니다.
💡 참고: 서로 완전 다른 파일(예: 승현.html / 미선.html)을 작업 중이라면, 내 작업이 모두 끝난 뒤 마지막에 합쳐도 괜찮습니다!

5. 기존 브랜치에서 n차 수정할 때 (반복 작업 루틴)

  1. 메인 최신화 내역 받기: git pull origin master
  2. 내 브랜치로 이동: git checkout feature/yg
  3. 최신 master 코드를 내 브랜치에 동기화: git merge master
  4. 파일 수정 및 저장(Ctrl + S) 진행
  5. git add . ➔ git commit -m "2차 수정 완료"
  6. git push origin feature/yg ➔ GitHub 접속 후 다시 PR 요청

6. 완전 새로운 기능 개발로 새 브랜치를 만들 때

  1. git checkout master (메인으로 이동)
  2. git pull origin master (최신화)
  3. git checkout -b feature/yg-v2 (새 브랜치 생성 및 이동)
  4. 작업 진행 후 동일하게 push + PR 요청
📌 주의: git checkout -b는 '새로운 브랜치를 처음 만들 때만' 사용합니다! 이미 있는 브랜치로 이동할 때는 -b를 빼고 git checkout 브랜치명만 사용하세요.
👑 [팀장] 코드 검수 & 메인 반영 & 팀장 작업 흐름

1. 팀원 PR 검수 및 Merge (최종 반영 과정)

  1. GitHub 저장소의 Pull requests 탭 접속 후 팀원의 PR 클릭
  2. Files changed 탭 클릭 ➔ 추가된 부분(초록)과 삭제된 부분(빨강) 검수
  3. 이상이 없다면 Conversation 탭으로 돌아와 Merge pull request ➔ Confirm merge 클릭
  4. 팀장 PC local 최신화: VS Code 터미널에서 아래 실행
    git checkout master git pull origin master

2. 팀장 본인이 직접 코드 올릴 때의 올바른 작업 흐름

팀장님도 master 브랜치 직접 수정 대신 전용 브랜치를 사용하여 PR로 합쳐야 안전합니다.

  1. 팀장 전용 브랜치 생성 및 이동:
    git checkout master git pull origin master git checkout -b feature/team-leader
  2. 코드 수정 후 저장 및 업로드:
    git add . git commit -m "팀장: index.html 메뉴 구조 수정" git push origin feature/team-leader
  3. GitHub에서 셀프 PR & Merge:
    Pull requests 탭 ➔ feature/team-leader를 master로 PR 생성 후 셀프 승인(Merge pull request)
  4. 내 컴퓨터 master 동기화:
    git checkout master git pull origin master
💡 한 줄 요약: master 브랜치는 보관 및 배포용으로만 사용하고, 팀장 포함 전원이 본인 브랜치에서 PR을 통해 master로 합칩니다.
🛠️ [번외] 기타 문제 해결 및 유용한 명령어

실수했을 때 대처법 (초기화)

  • 특정 파일 로컬 수정 내역 강제 취소:
    git restore 미니프로젝트/영근.html
  • 작업 중인 폴더 전체 수정 내역 강제 취소:
    git checkout .
  • 언제든 GitHub의 최신 메인 코드 가져오기:
    git pull origin master
